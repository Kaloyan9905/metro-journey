## 📖 Условие на задачата

Пълното условие е достъпно на:
- **Български:** [docs/problem-statement-bg.md](docs/problem-statement-bg.md)
- **Английски:** [docs/problem-statement-en.md](docs/problem-statement-en.md)

### Кратко описание

Пътник иска да пътува с метро от станция 1 до станция N. Той може да прескача станции, но **задължително трябва да спре** на всяка станция, чието име съдържа определен ключов низ. Задачата е да се намери минималният брой станции за посещение.

### Формат на входа

```
T                    ← брой запитвания
N₁                   ← брой станции за запитване 1
станция_1
...
станция_N₁
ключ₁
N₂                   ← брой станции за запитване 2
...
```

- `output/output.txt` - очаквани отговори

### Стъпка 3: Тестване на решение с Judge

```bash
# Направи judge.sh изпълним (само веднъж)
chmod +x judge.sh

# Тествай решение
./judge.sh main-OptimalApproach.cpp
./judge.sh main-GreedySorting.cpp
./judge.sh main-NaiveApproach.cpp
```

Judge скриптът автоматично:
1. ✅ Компилира решението
2. ✅ Изпълнява го с `input/input.txt`
3. ✅ Сравнява изхода с `output/output.txt`
4. ✅ Показва резултати, време и брой успешни тестове

### Стъпка 4: Ръчно тестване (опционално)

```bash
# Изпълни решение и виж изхода
./optimal < input/input.txt

# Сравни с очаквания изход
diff <(./optimal < input/input.txt) output/output.txt
```

## 🧮 Алгоритми и Решения

### Решение 1: Наивен Подход
**Файл:** `main-NaiveApproach.cpp`

| Параметър | Сложност |
|-----------|----------|
| **Време** | O(T × N × M × L) |
| **Памет** | O(N × M) |

Ръчна имплементация на substring търсене.

---

### Решение 2: Greedy Подход
**Файл:** `main-GreedySorting.cpp`

| Параметър | Сложност |
|-----------|----------|
| **Време** | O(T × N × M) |
| **Памет** | O(N × M + K) |

Събира задължителните станции в списък. Използва допълнителна памет за съхранение на индексите.

---

### Решение 3: Оптимален Подход
**Файл:** `main-OptimalApproach.cpp`

| Параметър | Сложност |
|-----------|----------|
| **Време** | O(T × N × M) |
| **Памет** | O(N × M) |

Едно преминаване с `string::find()`. Минимална памет - не пази списък със задължителни станции.

> **Забележка:** Решения 2 и 3 имат еднаква времева сложност. Разликата е в използването на памет - Optimal не заделя допълнителен вектор за mandatory станциите.

## 🧪 Система за тестване (Judge)

### Използване

```bash
./judge.sh <solution.cpp>
```

### Какво прави Judge

1. **Компилира** решението с `g++ -O2`
2. **Изпълнява** го с входа от `input/input.txt`
3. **Сравнява** изхода с `output/output.txt`
4. **Показва** резултати:
   - Брой успешни/неуспешни тестове
   - Време за изпълнение
   - Процент успеваемост

### Възможни резултати

| Резултат | Значение |
|----------|----------|
| ✓ Компилацията успешна | Кодът се компилира без грешки |
| ✗ ГРЕШКА ПРИ КОМПИЛАЦИЯ | Има синтактични грешки |
| ✗ RUNTIME ERROR | Програмата крашна (segfault, etc.) |
| ✗ Test X: Expected Y, got Z | Грешен отговор на тест X |
| ★★★ ВСИЧКИ ТЕСТОВЕ ПРЕМИНАХА | 100% успеваемост |
